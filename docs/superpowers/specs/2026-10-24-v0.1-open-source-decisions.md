# YoungCrow open source: decisões do /grilling (2026-10-24)

## Produto
- Público: dev solo e time pequeno que já usa Claude Code e/ou Codex.
- Diferencial: "Prova, não promessa" (decisão e entrega ligadas à fonte e à evidência no vault, instalação reversível, governança de capacidades).
- Promessa da v0.1: memória e prova + kit de regras e skills + esteira, com tabela de estado honesta (esteira "em desenvolvimento").
- Ecossistema: compor, não competir.
- Sucesso em 6 meses: 3 a 5 usuários externos reais, 1 PR externo aceito, autor usando em 3+ projetos.
- Manutenção: projeto pessoal aberto (issues semanais, PRs pequenos, roadmap público, sem SLA).
- Depois da v0.1: adoção antes da esteira.

## Distribuição
- Um repositório, um marketplace, dois plugins: `youngcrow` (núcleo) e `youngcrow-missions` (experimental). Versão inicial 0.1.0, semver, tag, release e CHANGELOG.
- Plugin nos marketplaces do Claude Code e do Codex (mesmo formato .claude-plugin; Codex lê).
- Primeiro uso: `uvx youngcrow init` (pacote mínimo no PyPI; nome `youngcrow` livre, verificado).
- Scripts Python em `.youngcrow/scripts/` no projeto, com manifesto de hashes; `init --upgrade` troca só o que não foi mexido; hook avisa versão divergente.
- Regras do harness em `.youngcrow/HARNESS.md`; CLAUDE.md com linha de import; AGENTS.md com bloco gerenciado entre marcadores.
- Reversão: undo simples (manifesto) por padrão + `--trial` completo (retrato atual).
- Migração das instalações antigas: `init --migrate` (hash das versões publicadas, prévia, remove só o não alterado).
- Canal: branch `stable` que só avança em release; `main` é desenvolvimento; tags para travar.
- Companheiros (`--companions`): superpowers, karpathy-guidelines, mattpocock (grill-me/grilling), humanizer. Automático nos dois clientes (Claude: escopo de projeto fixado em sha; Codex: perfil do usuário).
- Perfil do autor opcional: taste-skill, gsap, ponytail, impeccable, ui-ux-pro-max, n8n/Cloudflare, hooks do impeccable, .env.example com Postgres/n8n.

## Conteúdo
- Idioma: inglês primeiro; português completo em docs, templates e mensagens do init (`--lang pt`); skills só em inglês.
- Regras: núcleo leve com leis 1 (medir antes de afirmar), 2 (segredo fora do git), 4 (parar quando divergir), 9 (um escritor por checkout); demais no modo rigoroso.
- Histórico (relatórios, medições, specs, planos) vai para `docs/history/`.
- Demo dos 5 minutos: retomada entre sessões, gravada no README.
- Comunidade: CONTRIBUTING curto, Contributor Covenant 2.1, SECURITY via relato privado do GitHub, templates de issue (bug, ideia) e PR.
- Clientes: Claude Code e Codex completos no CI; macOS experimental com job no CI.

## Escopo e prazo
- PR #24 (worker OCI): congelado; extraído depois para `youngcrow-missions` em PRs menores.
- Lançamento: v0.1 só com tudo pronto e provado em instalação limpa (Linux, Windows; macOS experimental) e demo gravada.

## Consequências técnicas (fatos verificados, não decisões)
- Codex: plugin leva skills, hooks e MCP; não leva agentes nem comandos; o init escreve o agente em `.codex/agents/*.toml`.
- Codex: instalação só por usuário; marketplaces git se atualizam ao abrir; hooks exigem confiança do usuário.
- Claude: `${CLAUDE_PLUGIN_ROOT}` muda a cada atualização; escopo de projeto grava em `.claude/settings.json`.
- O `version` do plugin precisa subir a cada release, senão a atualização não chega.
- Publicar no PyPI exige que o autor crie o projeto e o "trusted publisher" no GitHub Actions.
