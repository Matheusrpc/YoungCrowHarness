# YoungCrow v0.1 open source: roteiro e plano P1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformar o YoungCrowHarness num harness open source que um dev solo instala com uma linha, atualiza sem perder o que escreveu e desfaz quando quiser.

**Architecture:** Um pacote Python `youngcrow` (PyPI, só stdlib em runtime) faz `init`, `upgrade`, `undo` e `migrate`, copiando os scripts para `.youngcrow/` no projeto e controlando cada arquivo por um manifesto de hashes. Skills, agente e hooks vão num plugin publicado no marketplace do Claude Code e do Codex. As regras do harness ficam em `.youngcrow/HARNESS.md`, ligadas ao `CLAUDE.md` por import e ao `AGENTS.md` por um bloco gerenciado.

**Tech Stack:** Python 3.11+ (stdlib), hatchling (só build), uv/uvx, unittest, GitHub Actions, marketplace `.claude-plugin`.

**Spec:** `docs/superpowers/specs/2026-10-24-v0.1-open-source-decisions.md`

## Global Constraints

- Python `>=3.11`; o pacote `youngcrow` e os scripts não têm dependências de runtime fora da stdlib.
- Nome no PyPI e comando: `youngcrow`; versão de desenvolvimento `0.1.0.dev0`, lançamento `0.1.0`.
- Layout no projeto, exatamente: `.youngcrow/VERSION`, `.youngcrow/manifest.json`, `.youngcrow/HARNESS.md`, `.youngcrow/scripts/`, `.youngcrow/requirements/`.
- Linha de import no `CLAUDE.md`, exatamente: `@.youngcrow/HARNESS.md`.
- Marcadores do bloco no `AGENTS.md`: `<!-- youngcrow:start -->` e `<!-- youngcrow:end -->`; no `.gitignore`: `# youngcrow:start` e `# youngcrow:end`.
- Nunca escrever através de link simbólico ou junction; nunca alterar notas do `vault/`, só criar os índices que faltarem.
- Arquivo alterado pelo usuário nunca é sobrescrito nem apagado por `upgrade`, `undo` ou `migrate`; é listado.
- Núcleo leve: leis 1 (medir antes de afirmar), 2 (segredo fora do git), 4 (parar quando divergir), 9 (um escritor por checkout).
- Inglês primeiro; português completo em docs, templates e mensagens (`--lang pt`); skills só em inglês.
- Testes com `unittest` (`python3 -m unittest discover -s tests`); testes novos põem `src/` no `sys.path`.
- Commits pequenos `<área>: <entregável>`, com a identidade Git do autor humano e sem linha de coautoria de IA (CLAUDE.md).
- Toda entrega atualiza o guia de uso afetado; o README é reescrito em P5.

## Review Focus

1. `CLAUDE.md` com fim de linha CRLF ou sem quebra final: o import entra uma vez e o `undo` devolve os bytes originais (teste na Task 2).
2. Marcadores do `AGENTS.md` quebrados pelo usuário (início sem fim): `upgrade` recusa sem escrever nada (teste na Task 6).
3. Projeto que já tem `scripts/vault.py` próprio: os scripts em `.youngcrow/scripts` não importam nem executam o arquivo do usuário (teste na Task 4).
4. `.youngcrow` ou `CLAUDE.md` como link simbólico: `init` recusa antes da primeira escrita (teste na Task 4).
5. `init` rodado duas vezes: a segunda recusa e não duplica blocos (teste na Task 4).
